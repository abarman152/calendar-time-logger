# ADR-024 — A flat app icon, delivered as `.icns`

Status: Accepted
Date: 2026-09-16
Supersedes the icon delivery and artwork parts of [ADR-019](ADR-019-app-icon-and-ctl-mark.md)

## Context

ADR-019 assumed that an asset-catalog `AppIcon.appiconset` whose artwork follows Apple's icon grid (1024 px canvas, 824 px continuous-corner body, 100 px margins) is drawn by IconServices without the macOS 26 gray compatibility plate. On macOS 27 that is not what happens.

Measured with `NSWorkspace.shared.icon(forFile:)` — what Finder, the Dock, Launchpad, and Spotlight actually draw:

| Delivery | Result |
| --- | --- |
| Asset catalog `AppIcon.appiconset` (grid artwork, 100 px margins) | Composited **onto a gray plate**, unmasked. The margins expose the plate, which reads as a light border around a dark icon. |
| Asset catalog `AppIcon.appiconset` (full-bleed artwork) | Still plated: the square artwork sits on the plate, with the plate's rounded corners visible around it. |
| `Resources/AppIcon.icns` + `CFBundleIconFile` (full-bleed artwork) | **Masked into the system squircle, no plate**, filling the tile like other app icons. |

The artwork itself also carried decoration that read as a border: a white hairline stroke inside the body edge, a baked drop shadow, a graphite gradient, and a purple-to-blue accent bar.

## Decision

- **Ship the app icon as `Resources/AppIcon.icns`** (`CFBundleIconFile`), generated by `scripts/generate-app-icon.swift` through `iconutil`. `ASSETCATALOG_COMPILER_APPICON_NAME` is cleared so no `CFBundleIconName` is emitted and the asset catalog icon is not used.
- **The app icon artwork is full bleed**, because macOS masks an `.icns` into the system squircle. The wordmark carries the margin and stays clear of the masked corners.
- **The mark is flat**: a solid black body and the white "CTL" wordmark. No stroke, no baked shadow, no gradient, no accent bar. macOS draws its own edge shading, as it does for every other icon.
- **The rounded shape is still generated** — an 824 px body with 100 px margins — for the images nothing masks: the `BrandLogo` the app draws itself (About, onboarding, the menu bar popover footer) and the DMG volume icon.
- `logo.png` at the repository root, the original artwork, is still unchanged.

## Alternatives considered

- **An Icon Composer `.icon` document.** Still the format Apple wants on macOS 26 and later, and still not authorable from a script (ADR-019 reached the same conclusion). `.icns` gets the same plate-free result today; this can be revisited with Icon Composer itself.
- **Keeping the asset catalog and making the artwork full bleed.** Measured above: the plate remains.
- **Keeping the hairline for definition on dark backgrounds.** It is what read as a border in Launchpad, which is what prompted this change. A flat black tile is what other dark app icons do.

## Consequences

- `scripts/package-dmg.sh` already accepted either `AppIcon.icns` or `Assets.car` in the bundle, and builds the volume icon from the rounded appiconset PNGs, so packaging is unaffected.
- The asset catalog keeps `AppIcon.appiconset` as generated artwork for the installer and documentation, but it is no longer the app icon. Anyone re-adding `ASSETCATALOG_COMPILER_APPICON_NAME` brings the plate back.
- Icon changes are only visible after the icon cache updates: replace the bundle, `touch` it, and restart the Dock.
