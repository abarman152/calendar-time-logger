# ADR-014 — SF Symbols as the template icon system

Status: Accepted
Date: 2026-09-16

## Context

Calendar Time Logger 1.0 stored a single emoji as each template's icon and showed it everywhere: the Dashboard, Work Logs, the menu bar, menus, notifications, and Shortcuts. Emoji can't be tinted, render inconsistently at small sizes, and don't match the native macOS look the redesign targets. The emoji is stored in `WorkTemplate.icon` and snapshotted into `WorkSession.templateIcon`, and both models belong to the versioned SwiftData schema (`CalendarTimeLoggerSchemaV1`) of a store that is already in daily use.

## Decision

- Template icons are **SF Symbol names**. The existing `icon` and `templateIcon` string properties hold the symbol name, so the SwiftData schema is **unchanged** and no store migration stage is needed.
- The symbols offered come from `SymbolCatalog`: 367 entries in 18 categories (Development through Nature), generated by `scripts/generate-symbol-catalog.py`. The script checks every name against the SF Symbols catalog installed with macOS (`CoreGlyphs.bundle` `name_availability.plist`) and fails for unknown symbols or symbols newer than macOS 27.0. It also copies the system's search keywords. `scripts/verify.sh --full` runs the check, and a unit test renders every catalog name with `NSImage(systemSymbolName:)`.
- `TemplateValidator` accepts only catalog symbols.
- **Migration of 1.0 data** is a value change, not a schema change. `PersistenceService.migrateLegacyIconsIfNeeded` runs once at launch (flag `migration.sfSymbolIcons.v1`), maps emoji in templates and session snapshots to symbols through `TemplateSymbol.legacyEmojiMap` (all 20 emoji the 1.0 editor offered plus common ones; variation selectors and skin tones are ignored), and uses `square.grid.2x2` for anything unmapped. It changes only the icon value, rolls back if saving fails, and is skipped while the store is unavailable.
- **Display never shows emoji.** `TemplateSymbol.displayName` resolves any stored value (symbol, legacy emoji, or unknown text) to a catalog symbol. `WorkLog`, the menu bar formatter, and the views use it, so unmigrated values can't reach the UI.
- Notifications can't show symbols, so their bodies no longer include an icon. Shortcuts show the symbol through `DisplayRepresentation.Image(systemName:)`.

## Alternatives considered

- **A new `iconSystemName` property with a V2 schema and a migration stage.** A cleaner field name, but it changes the schema of a store in daily use; a mismatched or failed migration would drop the app into its read-only in-memory fallback. Reusing the string column has no schema risk.
- **Reading the system SF Symbols catalog at runtime.** Always complete, but those files are private and undocumented, and many symbols are poor template icons. A curated, validated list is stable.
- **Keeping emoji as an option.** Rejected by the product requirement that no emoji appear in the UI.

## Consequences

- Every template, work log, menu, and menu bar item uses native symbols that adapt to appearance and Increase Contrast.
- After 1.1.0 migrates a store, Calendar Time Logger 1.0 would show symbol names as text if run against it. Downgrading isn't supported.
- Adding symbols means editing the generator script and regenerating `SymbolCatalog+Generated.swift`.
- The emoji text field and the system character viewer (`NSApp.orderFrontCharacterPalette`, listed in [ADR-002](ADR-002-swiftui-primary-ui.md)) are no longer used.
